# 映射与实体手柄隐藏

从 0.8.0 起，「设置与组件 → 手柄隐藏 → 映射时自动隐藏实体手柄」默认开启，保存在本机，所有游戏配置共用。已经手动维护隐藏规则的用户可以在停止后关闭它。自动隐藏启用但不可用时，映射会停止并说明原因。

| 操作／状态 | 实体手柄 | 虚拟输出 |
| --- | --- | --- |
| 待机、仅观察、手柄操作界面 | 不新增隐藏规则 | 不发送游戏输入 |
| 开始映射 | 先登记实际引擎读取权限，保存恢复记录，再隐藏所选实体 HID 与可确认的物理伴随接口 | 建立输出后检查设备可见，再发送映射输入 |
| 热更新、配置切换、校准 | 保留隐藏会话 | 先释放旧输入；更换输出后重新检查可见性 |
| 设备断开、等待原接口重连 | 保留会话和规则，不改选其他接口 | 释放输出，重连后重建并核验 |
| 停止、F12、启动失败、输出故障、正常退出 | 输出释放后恢复本次新增规则 | 停止发送并释放按键／摇杆 |
| 引擎退出、失去心跳 | 独立恢复进程处理本次规则 | 独立输出所有者先发布中立报告 |
| 恢复进程也崩溃或驱动暂不可用 | 保留磁盘恢复记录，下次启动或手动恢复重试 | 不自动恢复映射 |

自动选择依据 Windows 设备树的实例与祖先关系。不会按照设备名称或相同 VID/PID 隐藏设备。只添加所选物理 HID 和同一物理设备的游戏/XInput 接口。0.8.2 优先使用实际 XUSB 接口对应的 USB 功能节点：复合手柄的 `MI_00` 等独立功能可与键鼠兄弟接口分开处理，无需隐藏公共 USB 父设备。XUSB 本身就是整个 USB 设备时，仍需核验整个相关分支，拒绝连带隐藏键鼠或未知功能。多个无法区分的手柄不会自动合并隐藏。只有 XInput 槽位而没有可定位设备路径的接口也会要求改选明确的 HID 接口，或关闭自动隐藏后手动管理。

HID 的游戏／键鼠／厂商用途同时从硬件 ID 和兼容 ID 读取；兼容 ID 为空是正常情况。祖先链中的 `ROOT\ACPI_HAL\...` 是系统电脑根节点，不表示手柄是虚拟设备。这个例外只影响来源判定，电脑根节点仍不能写入隐藏列表；HidMaestro、ViGEm 和其他软件根仍被排除。

HIDMaestro 输出辅助进程返回自己创建的键盘、鼠标、手柄及 XUSB 伴随节点实例。开始输出前核验这些节点及祖先不在隐藏列表中。兼容模式检查本次创建的新虚拟设备。已有规则遮住虚拟手柄时会阻止启动并提示处理，不擅自解除其他软件设置的规则。

恢复记录 `hidhide-session.json` 在应用数据目录，与手动规则记录 `hidhide-motion-rules.json` 分开。记录在第一次驱动写入前原子落盘，保存本次新增项和原策略摘要。停止时只删除新增项，保留原有隐藏项与应用权限。引擎读取权限保留，防止仍由用户隐藏的实体手柄锁住引擎。仅在全局隐藏开关原先关闭且没有其他策略变化时，恢复原来的关闭状态。

恢复进程以普通用户身份运行，使用限制消息类型的私有管道、随机令牌和进程身份校验，不提供任意驱动操作或执行命令的接口。运行时每 400 ms 续约，正常阶段心跳超时为 2 秒；输出准备阶段允许最长 120 秒等待设备创建/授权，但父进程死亡立即触发回收。异常路径留出 500 ms 给独立输出所有者释放输入。无法确认恢复时保留记录并显示错误；停止后可以点击「恢复本应用的隐藏规则」重试。

建议先启动映射，再启动游戏。已经打开实体设备句柄的程序可能需要重启或重新枚举设备才能观察到可见性变化。Windows 的实际设备枚举、驱动可见性及游戏行为仍需用户手动验收。

从 0.15.2 起，Studio 停止映射时可继续持有仍在线的实体手柄连接。再次启动同一接口会复用该连接。游戏侧仍会看到自动隐藏规则导致的实体设备可见性变化，ViGEm 的虚拟手柄也随输出会话创建和释放。

驱动控制复用固定 FlexInput 提交的 `crates/hidmaestro/src/hidhide.rs`；设备关系复用 `crates/devices/src/devnode.rs`，Studio 只维护选择、所有权、日志和生命周期。上游源文件关于必须提权及 XInput 无法隐藏的历史注释不能替代当前官方说明，移植注释已指出这一差异。参考 [HidHide CLI 官方说明](https://docs.nefarius.at/projects/HidHide/CLI-Usage/) 与 [原生 API](https://docs.nefarius.at/projects/HidHide/API-Documentation/)。
