# Studio interaction over FlexInput

The product is a Studio-style configuration and interaction layer over FlexInput. Users work with games, actions, gyro settings and profiles; internal processing graphs remain an implementation detail. Reuse existing FlexInput behavior before writing an alternative. The source stays pinned to `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` (0.16.9) so upgrades are reviewable.

For the complete upstream crate inventory, the current 0.8.0 integration and remaining optional scope, see [FlexInput 模块与接入范围](flexinput-module-plan.md).

## Current boundaries

| Responsibility | Implementation | Necessary Studio adaptation |
|---|---|---|
| Mapping evaluation, standard gamepad mapping, RWS | FlexInput core and engine graph/evaluator modules | Translate game/action settings into the graph; feed timestamped samples and expose telemetry |
| In-game angle calibration | `processing.rws` measurement mode and upstream `CalFlick` | Feed the selected processed stick from the input bus, isolate its regular mappings, and save the measured scale through a game overlay |
| Node definitions | Selected original `flexinput-modules` descriptors for processing, logic, math and generators | Build Studio graphs using upstream output metadata; preserve additional dynamic outlets and Studio source/sink nodes |
| Coordinate spaces, orientation, IMU estimation | FlexInput 3DOF/IMU implementations | Activation, device calibration, profile lifecycle and Studio settings |
| Curves, One Euro, decay, brake, angle snapping | Original `eval/modules/jsm/cc.rs` through the headless API | `motion_curves.rs` is a compatibility re-export for Studio profiles |
| Input and output timing | FlexInput `start_io_thread` deadline rules, `HrWaiter` and Windows `display_clock.rs` | Headless I/O loop supplies SDL FIFO work and scheduled device submission |
| Continuous HID mouse | FlexInput `keymouse_hm.rs::flush` behavior: accumulated displacement, default 500 Hz cadence, raw publication, signed count carry and one neutral transition | Consume Studio's already integrated displacement exactly once; preserve discrete chord/scroll ordering; cancel queued output on stop/switch |
| HID transport, keyboard/mouse descriptors, gamepad encoding, GIP, feature answers, driver deployment | Pinned FlexInput HIDMaestro client and payloads | Studio-owned fixed-profile helper, device ownership, consent entry, error reporting and crash protection |
| SendInput / ViGEm compatibility mode | Existing Studio Windows adapter remains during migration | This is a retained compatibility implementation, not claimed as fully migrated to FlexInput's enigo wrapper; its guardian and bindings must remain compatible before replacement |

## 0.6.1 mouse correction

0.6.0 reused the native driver/client but added an inline ACK wait to every mouse report in the SDL processing thread. A slow confirmation could block sample processing, create a backlog, and trigger the existing 50 ms stale-input reset. This was a Studio adaptation error, not evidence that FlexInput itself had the same problem.

The 0.6.1 correction separated synchronous HID confirmation from input processing. It accumulated mouse displacement between 500 Hz output ticks and carried fractional counts forward. Like upstream, the mouse emitted one zero-motion transition and stayed idle afterward.

Studio kept confirmation on a worker for discrete key, button, scroll and release boundaries. A bounded ordered queue, generation cancellation and a release/join boundary prevent a stopped profile from replaying old movement into the next one. The main runtime owns the safety lease.

`vendor/flexinput/crates/virtual/src/keymouse_hm.rs` and `crates/ui/src/app/threads.rs` retain the original reference source and hashes for comparing the adapted scheduling code; these references do not pull the FlexInput UI into the application. The original `hr_timer.rs` and pure curve file are compiled directly. 0.6.1 checked 111 vendor files; 0.7.0 checks 141.

## Input and output schedule

`crates/virtual/src/io_schedule.rs` extracts the timing portion of `crates/ui/src/app/threads.rs::start_io_thread` at `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`. Separate absolute deadlines drive input polling and output. The rules carry over the quarter-period slack, stall recovery, measured preparation lead, high-resolution waits and Windows I/O priority. The original `crates/virtual/src/display_clock.rs` supplies vblank tracking, VRR and `PreciseWait`. Studio converts the persisted polling and output rates to periods for the headless `IoSchedule::begin`, and `crates/host/src/runtime.rs::output_pass` submits the output when due. Both rates default to 500 Hz and accept 60–4000 Hz, with the upstream setting of zero selecting the polling rate for fixed output. Display sync schedules four slots per frame and falls back to four times the nominal refresh rate, with 60 Hz as the nominal rate until a display is known.

The Studio adapter polls SDL once per input deadline and evaluates each event from the timestamped FIFO on the I/O thread. This retains gyro sample clocks and button edges. At output deadlines it advances held-stick aim, Flick Stick and timed turns, then submits accumulated mouse displacement and the latest virtual gamepad axes. Digital gamepad edges still submit immediately. The HID keyboard and mouse adapter uses the raw mouse write and single neutral transition from `keymouse_hm.rs::flush`. The worker still confirms discrete edges and releases. If an edge is pending, movement joins the ordered queue behind it. That queue also handles descriptor-sized overflow and generation cancellation. The pinned manifest covers 152 files.

## In-game angle calibration

The overlay also offers a default **trial 360° turn** with an editable, unsaved scale. The pinned FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`, `crates/engine/src/eval/modules/rws.rs::{compute_rws,tick_bound_turns,stick_turn_fit}` and `eval/modules/jsm/cal.rs`, supplies the reference angle/count and stick-capacity semantics but has no headless command for an isolated overlay trial with a temporary scale. Studio adapts its existing `Engine::advance_turns`/`PendingTurn` path (also used by timed turns and the Flick stick angle budget), rather than introducing another Flick recognizer. A mouse trial spreads 360 degrees of counts over one second; a right-stick trial releases 360 degrees through the normal full-stick capacity budget, including the fractional last interval. These are scale checks, not a reproduction of every Flick easing/duration setting and not automatic observation of the game camera.

The trial is revision-bound and participates in the existing measurement lifecycle, output dispatcher, F12/fault release and input-backlog interruption handling. Physical mappings, gyro and touch output are isolated during the trial; a timing interruption retains isolation until cancellation. Completion releases on the following output tick, after the final axis interval. The native overlay allows editing its scale without writing the profile, restores the previous game focus before emitting when editing activated the window, and saves through the existing profile path. The original manual yaw/pitch measurement remains under more calibration methods, uses the same temporary scale and fills the draft on completion. Temporary RWS scale overrides are restored on measurement end/reset. Protocol 13 adds the trial command and the optional manual measurement scale. No vendor source or hashes change.

For virtual-stick calibration the UI asks users to select a linear in-game stick response and disable edge/turn acceleration. A scalar still cannot compensate for startup acceleration, different vertical limits or nonlinear partial-stick response. Automatic trials use the configured output mode; they do not require a gyro sensor, while manual measurement retains its gyro/pointer-mode requirements.

The Studio gyro graph uses `cal_measure` and `cal_output` in the original `crates/engine/src/eval/modules/rws.rs::compute_rws` at `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`. Its second input receives the configured Flick stick's processed vector on each timed gyro sample during yaw measurement. The existing `rws_calibration.rs` headless extraction of `Flick` from upstream `eval/modules/jsm/cal.rs` supplies the rim tracking, smoothing and angle accumulation. The same evaluator combines the stick and gyro, drives the selected output, and reports signed degrees and peak stick deflection.

Studio's controls use a separate graph. The adapter neutralizes the selected stick on that graph's input bus during calibration and continues feeding its original processed value to RWS. The desktop overlay keeps game focus, pins the measurement to the running base profile and revision, and uses the engine's final result to update only the calibrated output scale through the existing profile save path.

Studio preserves the RWS measurement accumulator on invalid accelerometer samples in modes that do not require acceleration. A mode that does require acceleration marks the measurement as interrupted. The host's calibration and pose reset transitions use the existing dispatcher release path before changing the engine. If release fails, the host enters its fault state instead of continuing to emit with the old output.

## 0.7.0 provider and contract integration

`flexinput-devices` compiles the original SDL provider, identification, layouts, native parser and supporting pure modules through a headless entry. Audio, MIDI, networking, dedicated-radio and USB/IP startup dependencies are excluded. The runtime uses the upstream all-SDL option, not the native HID polling providers. Their timestamped interfaces remain future work; merely compiling a parser does not claim that its reader is active.

The event seam captures SDL gamepad events before the upstream sensor pairing/filtering/average. It keeps identical samples, sensor and host clocks, button down/up and axis order. Its bounded queue faults on overflow. It lets SDL's internal watcher translate joystick events, then flushes the unused joystick queue without pumping window messages. Selection/switch resets the capture queue; enumeration only probes capabilities and releases unselected pads. Sensor enablement and the upstream frozen-stream watchdog belong to the selected provider; UI navigation disables sensors.

Studio's former SDL event parser/reader is removed. `crates/engine/src/sdl.rs` is now a device DTO, discovery-settling and lifecycle bridge plus the synthetic verification fixture. Coordinate permutations call the original upstream functions. The unmodified official SDL 3.4.18 remains the sole SDL runtime; sdl3-rs 0.20.0 and sdl3-sys 0.7.1 are bindings only. SDL is pinned to `libsdl-org/SDL` commit `829a65d769d935c4852f8159e964312c0957260a` (`release-3.4.18`). The DLL and official x64 import library are pinned in `vendor/sdl3/manifest.json`, respectively SHA-256 `2b4b128d8d510cc2d442693cf848c050d700d43dc667afe9e5fd82b0570d667e` and `c60802d826fe9a724f824ecdeac1f422bdf53a53705ef32eb12dd73e5d566e2c`. MSVC delayed imports let the engine preload the absolute DLL path; the module remains pinned across stop/reconnect so cached import thunks cannot reference an unloaded DLL. Builds inspect the PE imports and reject static/source SDL features.

On 2026-11-11 the maintainer reported that Apex 6 Pro firmware fixed the gyro-axis issue and requested removal of the custom `SDL_hidapi_flydigi.c::HIDAPI_DriverFlydigi_HandleStatePacketV2` device-150 transform. The official DLL replaces that build without another vendor-specific correction in the adapter; standard upstream coordinate conversions and timestamped FIFO processing stay unchanged. `crates/devices/build.rs`, a Studio-added build entry over FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`, now selects the official import library in `vendor/sdl3` and tracks it for relinking. The retired artifact hashes and original measurement limits remain in `vendor/sdl3/README.md` and Git history. Firmware versions were not supplied, and no hardware validation is claimed for this retirement.

The release engine is built in a separate explicit x64 target directory with `crt-static` applied to every target dependency, including hidapi's C build. Applying it only to the final executable mixes C runtimes and fails to link. The desktop build retains its own cache/CRT choice; only the verified resulting engine is copied into resources and the conventional release location.

`flexinput-modules` supplies the original selected node descriptors. `flexinput-virtual` supplies the original output-device contract and layouts through a headless entry. `FlexVirtualSink` translates existing Studio atomic outputs into those pins and reports failures back to the dispatcher. Studio uses the HIDMaestro transport and retains the SendInput/ViGEm compatibility path. The headless entry keeps ownership of devices and outputs in the Studio worker.

The new source set verifies 24 original files against the pinned Git tree blob IDs, preserves their original SHA-256 values, and records 6 added headless/build/event API files separately. Original root `lib.rs` entries retained for reference are not the build entry. Modifications to the SDL provider expose raw events and lifecycle options; other source changes isolate dependencies and disable upstream tests that enumerate physical devices. Automated tests never enable those hardware paths.

## 0.8.0 mapping visibility lifecycle

The native control surface is the original `crates/hidmaestro/src/hidhide.rs` at the same pinned commit. Its original Git blob and SHA-256 are retained; the port adds checked opening, checked list/flag reads and inverse-mode inspection. Failed reads never become empty policy. The headless HIDMaestro entry exports it. The devices headless entry exposes the existing `devnode` helpers and includes the XInput instance ID, enabling topology selection without another enumeration implementation. Current integrity coverage is 142 vendor files.

Studio owns a write-ahead session journal, physical target selection and an ordinary-user recovery companion. The pinned upstream helper has broader responsibilities and is not imported wholesale. Official HidHide documentation permits ordinary-user control and describes physical XInput/USB masking; historical upstream elevation/HID-only comments are explicitly annotated. ## 0.8.0 practical feature review

The 0.8.2 visibility correction remains in Studio's topology adapter. A complete physical USB ancestry reaches `ROOT\ACPI_HAL\...`, so that computer node is neutral ancestry while still forbidden as a hide target. HID roles combine hardware IDs and compatible IDs through the existing `devnode::strings_property`; ordinary HID collections can have an empty compatible-ID list. The original `xinput_devnodes` reports the actual XUSB interface instance. On composite controllers the adapter masks that independent USB function and its gaming HID children, keeping keyboard/mouse/unknown sibling functions outside the affected branch. If XUSB is the common USB parent, the original shared-function rejection remains. No vendor algorithms or driver payloads change. Regression fixtures reproduce the APEX 6 layout without a device-model whitelist or live driver writes.

After the input/output integration, the pinned implementation was reviewed for practical functions that fit Studio's action-based UI. The following additions now execute the original implementation, rather than an independent timing or geometry algorithm:

| Feature | Pinned implementation | Headless adaptation and Studio ownership |
|---|---|---|
| Hold, short, long, double, press-edge, release-edge | `engine/src/eval/activation.rs::apply_press_mode` | The opaque `PressGate` accepts timestamped input; Studio supplies action configuration, same-chord hold-back, chord priority, snapshot suppression and lifecycle resets |
| Turbo | `activation.rs::apply_turbo` | The gate runs first, then turbo with a separate action period; existing wheel repeat remains a separate Studio option |
| Radial inner/outer stick areas | `core/src/area.rs::{AreaLayout,Border,Shape}` and `band_of` | Existing geometry is configured as a circular ring; Studio adds bounded per-stick thresholds, hysteresis, a neutral exclusion and ordinary named action inputs |
| Stick rebound suppression | `engine/src/eval/device_cal.rs::StickRebound::step` | Only type and method visibility changes; Studio exposes a bounded optional duration and advances expiry when no further axis event arrives |
| Physical controller hiding | `hidmaestro/src/hidhide.rs`; `devices/src/devnode.rs` | Original native control and topology queries; Studio owns checked policy, exact output-node protection, write-ahead journal and recovery lease |

The activator port includes one behavior correction: once the second double press has been recognized, its held state is no longer cancelled by the recognition window expiring. Recognition still expires before the second press. The original SHA-256 for `activation.rs` is `df3820738330d9e85339b0e5e4a032dd9b296fa5b73102dd6263df0e4118aa85`; for `device_cal.rs` it is `0a7f3810f3150c47012dc0ddaed26324b83af28015baf46272022727973e53fe`. The vendor manifest retains the original hashes and Git blobs, current hashes and patch notes.

The headless `PressGate::sample_at` in `crates/engine/src/eval/activation.rs` adapts the press modes from FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` to SDL event timestamps. It shares the upstream long output, pulse and turbo logic. As in `eval/modules/remapper_hold_back.rs::hold_back_tick`, a withheld tap replays on release and a new press ends a replay. The Remapper's per-pin bus masking does not match Studio's action-level chord ownership. Studio supplies the first long threshold for each equivalent input condition so that the ordinary action can only replay before that deadline. The native sampled Remapper still uses its original clock. The Studio host advances the event clock after draining the SDL FIFO, independently of the continuous-output schedule.

Digital gamepad mappings use the same action compilation and activation path as keyboard/mouse mappings. The saved gamepad entries gain optional activation fields with legacy defaults. Whole-stick and trigger-travel wires continue to use the native sink graph. Same-condition competition uses the latest short cutoff, earliest long threshold and latest double window across both output families. The native Remapper permits multiple timed cards over the same input to fire, so the timestamped adapter adds a shared decision rule for long versus double and delays ordinary/short/release commands until that decision finishes. Double recognition, output pulses, long output and turbo reuse the native activation functions. An explicit simultaneous-output option bypasses this competition for an individual binding.

Eight-way stick overlap exposes the existing `StickMode::NoMouse` direction predicate in `eval/modules/jsm/analog.rs`, from the same pinned commit, through `jsm/mod.rs` and `modules/mod.rs`. The native JSM caller and Studio call the shared predicate. Studio selects the layout per stick after physical calibration and deadzone processing, and applies each action's threshold to radial magnitude in this layout. Existing configurations default to component thresholds. JSM directional imports select overlap and a zero action threshold (the source deadzone remains active); the import report still calls out deadzone and other stick-mode differences.

General hold layers are a Studio configuration adapter over the existing engine. Their sparse patches inherit unmodified fields, replace actions by canonical input and stack in explicit order. All nonempty combinations of the bounded eight layers are validated before accepting a configuration. Runtime reconfiguration preserves the sample clock, input bus, unchanged activator state, shared held outputs and current virtual device. Changing a timed competitor or direction layout cancels affected pending gestures; reordering identical rows preserves progress. No dedicated ADS branch was added. Hold modifiers use physical inputs and base geometry so a layer cannot invalidate its own trigger by changing a ring or filter. This follows the user-facing inheritance principle in [Steam Input action set layers](https://partner.steamgames.com/doc/features/steam_controller/action_set_layers?l=english), not its API or a claim of complete Steam Input behavior parity.

The base-profile signal path also supplies scalar stick axes for hold modifiers. After applying a layer, Studio samples the resolved controls before evaluating gyro toggle and fixed-angle turn edges. Mode changes clear the previous mode's virtual-stick contribution. The adapter keeps the `processing.gyro_3dof` graph from `eval/modules/gyro3dof.rs` at `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` intact when the layer only changes Flick, motion bindings, fixed turns or the separately reconfigured custom filters.

Recording now uses an output-only pause lease. It retains the input, output device and visibility session, suppresses all automatic profile switching, and resumes only after neutral physical controls. The Windows profile-switch overlay and UI localization belong to the Studio shell; neither is a competing input or motion implementation.

If the host discards a stale input batch, it releases output and rebuilds the physical baseline only after draining the FIFO. It uses the pinned `crates/devices/src/sdl_raw.rs::event_snapshot` seam over FlexInput `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`. Recording sees the restored neutral-control state without capturing synthetic edges. An interrupted angle measurement stays isolated until the user finishes or cancels it.

Guided binding setup extends that same lease across the whole queue. The main view and the always-on-top recording window share the Studio action list and focused WebView keyboard and mouse capture. The existing engine lease keeps the FlexInput SDL provider (`flexinput-devices`, pinned `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`) and virtual device attached while output is paused. Both entry points produce existing Studio `Action` output strings and retain the same validated profile format.

Reviewed further candidates remain explicit:

- **Basic rumble return:** useful next integration. It spans `VirtualDevice::poll_outputs`, feedback routing and `DeviceBackend::send`. The current sink handles inputs but does not route game feedback to the physical device; preserving selected-device identity, output ownership and disconnect release requires a separate bounded integration and real-device acceptance.
- **Additional touch zones / gestures:** upstream area and touch helpers are relevant, but touch coordinates and contacts must first be exposed by the live timestamped input path. Current SDL event seam carries gamepad buttons, axes and sensors; compiled parsing code is not equivalent to live contact support.
- **Native HID providers:** potentially useful for device-specific reports; still deferred until they expose the same raw clocks, FIFO transitions and overflow contract as the active SDL provider. Replacing a working event path with a sampled poll would violate the existing contract.
- **DualSense adaptive triggers, audio/haptics, dedicated radio, Joy-Con 2, USB/IP and networking:** retain as optional device/product scopes. They need additional device, feedback or transport contracts and are not prerequisites for the current mapping features.
- **Multiple-device motion fusion:** excluded as requested. Single-device gyro, accelerometer, orientation and gravity-relative processing remain enabled.

These candidates were inspected, not silently enabled. The user guide explains the shipped features and their limits in [action-layers-and-triggers.md](action-layers-and-triggers.md).

## 0.9.1 keyboard output coverage

Keyboard coverage is now driven by a shared Studio key catalogue used for the picker, physical-key recording, profile validation, modifier ordering and Windows virtual-key conversion. The headless `flexinput-virtual` entry exposes the original pure `key_name_to_hid_usage` lookup extracted verbatim from `crates/virtual/src/keymouse_hm.rs` at c69f53ad3bca4ed34ef5f2d63509addaa7c767be. Only the lookup's visibility changes; it does not compile the upstream GUI/device owner or alter transport. The source file and derived API retain their hashes and provenance in the vendor manifest.

Studio adapts its existing key identifiers (ESC, UP, etc.) to the original lookup. Standard number-pad keys, Num Lock, Scroll Lock, the application key and F21–F24 are absent from that upstream lookup; their catalogue entries explicitly use the USB keyboard-page usages verified against the already pinned SDL scancode definitions. Left/right modifier bits follow the original HIDMaestro modifier byte. F12 remains excluded because the input engine owns emergency stop. Media/consumer-page keys are not offered by the boot-keyboard sink. No driver or descriptor change is required.

The existing Caps Lock gap was in Studio's selected subset, rather than upstream support: the original lookup already maps it to usage 0x39. Esc was already supported by the sinks but was intercepted by recording cancellation. The editor exposes an explicit assignment while preserving Escape-to-cancel.

## 0.10.0 custom processing seam

The pinned `crates/engine/src/eval/registry.rs` has internal, static module hooks; it does not expose a user-script runtime or external registration interface. Studio therefore adds the optional `motion-filters` crate and three per-sample processing seams around the existing motion adapter. The original FlexInput coordinate projection, built-in filtering, curves, input provider and output transports remain the execution path around those seams. No second built-in filter implementation replaces them.

Rhai 1.27.0 implements the first `SampleProcessor` backend. It compiles source off the sample path, binds private state through the documented `this` contract, and accepts timed numeric values only. Ordered instances share a sample operation budget and report faults as sticky bypasses. The profile and UI adapt configuration, parameters, layers, diagnostics and synthetic preview. These are missing application contracts rather than a rewrite of an upstream algorithm. Timestamp FIFO, measurement bypass and session ownership stay in the existing engine. The headless preview CLI links only the pure filter crate.

The time-based EMA and median scripts are authoring examples of the extension interface, selected explicitly by users; existing default algorithms continue to use FlexInput. Rhai license texts are retained under `licenses/`, with its exact version in Cargo.lock.

## 0.10.0 native output integration

The original `virtual/src/hidmaestro_device.rs` is compiled directly through the headless entry, with `sony_feedback.rs` and the original HIDMaestro helper client modules. The helper client is linked for the original type's API; Studio opens sections created by its existing constrained lifecycle owner and does not call the original global helper creation entry. The original `apply_pin` function is exposed from a derived source file with only its visibility changed. Native HID/GIP encoding and device flush/reset remain original code. Native device tests that open shared sections are opt-in, so automatic checks cannot attach to another application's output section.

The ViGEm Xbox/DS4 classes are derived from the gamepad section of `virtual/src/windows.rs`; keyboard/Enigo and optional composite USB startup stay outside this entry. The headless derivation adds fallible `flush_checked` methods and an Xbox player-index accessor: the original report construction, target creation, feedback and reset bodies are retained, while errors previously discarded by `flush` are returned to Studio's release-on-fault lifecycle. Original `flush` delegates to the checked method. Source files, derived ranges, original hashes and current hashes are recorded before vendor checks are updated. This exposes existing implementations rather than adding new report algorithms.

Studio selects keyboard/mouse and gamepad backends independently. Standard Xbox/DS4 output defaults to native ViGEm, while native HIDMaestro gamepad output remains an explicit choice. HIDMaestro readiness requires the owned companion's original `orchestrator::node_diag` to confirm a started, problem-free XUSB interface; a global interface count or shared-memory handshake alone is insufficient. ViGEm uses its original target readiness and Xbox player index. Studio forwards actual target metadata through all sink wrappers. HidHide protection includes the virtual nodes enumerated during native ViGEm creation, using the existing read-only topology inventory; no devices are disabled or reordered.

For each capability, identify the upstream module, the callable interface and the missing Studio contract. Expose a small headless API when the implementation exists but is coupled to the upstream app. Keep configuration conversion and runtime ownership in Studio; move reusable processing and transport behavior into the pinned FlexInput layer. Preserve behavior with contract tests before removing an adapter. A module is not considered migrated merely because it uses the same driver or imitates its name.

## 0.11.0 feedback and touch integration

This integration exposes the existing `DeviceBackend::send` path on the same selected SDL `OpenPad`, and the existing `LedOut::due` flush for event-mode sessions. It does not open another controller, run sampled `poll()`, change the native rumble encoder or replace native LED coalescing. Native virtual devices expose a monotonic feedback-command sequence so capture, configuration switches and reconnect can suppress old latched feedback until a fresh game command arrives; their report decoding and notification contents remain original.

The timestamped SDL seam also retains touch down/motion/up events, using the original provider's single-pad/two-finger and split-pad coordinate convention. Native `eval_graph_tick` with `route_touchpad` runs the original `eval/trackpad.rs` state machine for pointer, two-finger scroll, tap and physical-click gestures. Studio supplies profile controls, contact previews and lifecycle baselines only. Recording and observing keep physical output disabled; entering mapping with fingers already held waits for a neutral baseline. Vendor API additions and event DTO changes are documented before their manifest hashes are updated.

Studio advances the `eval/trackpad.rs` state machine from FlexInput `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` on control events and drained input timestamps. Output deadlines may run ahead of queued contacts, so they only submit the resulting mouse and button reports.

The real-DLL synthetic check caught the upstream initializer disabling all gamepad events before the event seam re-enables its chosen types. `devices/src/sdl_backend.rs` therefore also re-enables the three native touch event types in raw mode, alongside its existing axis/button/disconnect set. The sampled provider remains unchanged. This is event subscription wiring, not replacement touch processing; the integration check requires all three injected transitions, their timestamps and coordinates before evaluating native pointer output.

## Adjustable Flick release

The initial mouse Flick in `crates/engine/src/eval/modules/jsm/aim.rs` at FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` uses `1 - (1 - progress)^2` and pays out the difference between successive cumulative angles. The generic `eval/modules/rws.rs::compute_flick` instead divides its remaining angle linearly over its remaining time. Studio uses that RWS entry and needs a configurable transition between those two release shapes while retaining its companion stick aim.

The vendor adaptation extracts the existing JSM expression into `eval/curves.rs::ease_out_quad`, which both existing JSM Flick call sites reuse. `flick_release_progress` accepts normalized strengths 0–1. Strengths 0–0.5 blend linear progress with that original easing using a blend weight of `2 * strength`. Above strength 0.5, cumulative progress follows `1 - (1 - progress)^(1 + 2 * strength)`. Strength 0.5 therefore reproduces JSM's quadratic easing, while strength 1 selects cubic ease-out for faster initial release with monotonic progress and bounded total angle. This stronger release is a Studio configuration extension to the upstream's fixed quadratic easing. `MAX_FLICK_RELEASE_EASE` supplies the shared runtime and validation limit. RWS accepts the optional `flick_release_ease` parameter, defaulting to zero for upstream callers. Two additional state slots retain the initial angle and duration so shaped releases follow cumulative time progress and finish by paying the exact remaining angle. Tracking, gesture classification, companion stick aim and sensor processing keep their existing entry points. The original upstream hashes and notices are retained, and the manifest records only these scoped changes to `curves.rs`, `jsm/aim.rs` and `rws.rs`.

Studio stores `gyro.motion.flick.release_ease` in profiles and layer overrides, with the 0–1 value displayed as 0–100%. New Studio configurations and missing fields default to 0.5 (50%). New JSM Flick imports also select strength 0.5 to reproduce the source configuration's release curve. Explicitly stored strengths use this revised scale. The slider and its progress preview call the same headless curve API. Studio continues to own validation, configuration lifecycle and output-capacity handling.

The original `crates/engine/src/eval/modules/rws.rs::compute_flick` at FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` uses a fixed ratio for the direction tracking threshold. The vendor adaptation accepts optional `flick_release_ratio` in the existing RWS node. Studio saves and validates `gyro.motion.flick.release_ratio` (0–1, default 0.5) and displays it as a percentage. With the parameter set, the tracking threshold is the engage threshold multiplied by the ratio, bounded by the 0.15 safety floor and the engage threshold. If the engage threshold is below 0.15, tracking uses that threshold as the floor. Upstream callers without the parameter retain the original formula.

The same node accepts optional `flick_disengage_ms` for the existing sustained release check. Studio saves it as `gyro.motion.flick.disengage_ms` (0–60 ms, default 10 ms, including profiles that omit it). Zero disengages on the first sample below the tracking threshold. Upstream callers without the parameter keep the original 60 ms hold. The heading dropout guard and initial-turn payout retain their existing logic. IPC protocol 15 carries both new profile fields.

The grouped settings UI continues to configure these same RWS parameters and the existing JSM `cc` filters at pinned commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be`. Curve previews still call the headless preview APIs. The UI displays the effective tracking threshold, exposes the same shared output/calibration fields from both motion and stick pages, and deletes existing layer patch keys when restoring inheritance. Section expansion, search/focus and numeric presentation remain frontend concerns; this layout change introduces no processing algorithm or additional vendor adaptation.

Studio routes gyro aim, Flick and companion stick aim through the resolved `gyro.output` after layer selection. `crates/engine/src/engine.rs::advance_flick_input` observes FIFO control events and drained input timestamps. The pinned `crates/engine/src/eval/modules/rws.rs::compute_rws` from FlexInput commit `c69f53ad3bca4ed34ef5f2d63509addaa7c767be` gains an optional `flick_input_dt` for this split-clock caller. Gesture timing and release detection use the input interval, while smoothing and turn payout use the output interval. An input-only call can latch a Flick between output slots without consuming its timed payout. The original caller defaults to one shared interval.
